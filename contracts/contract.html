FamilyOS · Buildathon integration spec

FamilyOS Data Contract

What the Financial Data Engine sends to the Family Context Engine. If your output validates against this contract, the context engine, agent and dashboard work with it unchanged. Nothing on the other side reads your database or depends on your internals.

schema_version 1.0 Contract A JSON · UTF-8 Synthetic data only

01Where this sits

You · Builder A
Financial Data Engine
Upload, OCR, extraction, normalisation, validation
→
This document
Contract A JSON
members + financial_records

Builder B
Family Context Engine
Relationships, history, consent, LangGraph Q&A

You are the source of truth for extracted facts. The context engine never edits your facts. It links them to people, works out which value is the latest, and reasons across family members.

02How to deliver data

Pick one. All three carry the same records.

Option 1 · Pull

You expose an endpoint

Return the full family snapshot. We start the context engine with FINANCIAL_ENGINE_URL pointing at you.

GET {FINANCIAL_ENGINE_URL}/families/{family_id}/financial-data
→ 200, body = full Contract A payload
Option 2 · Push

You send new records to us

Send records as each document finishes processing. The response tells you which older fact the new record replaced.

POST http://<context-engine-host>:8000/api/family/F001/records
{"schema_version":"1.0","family_id":"F001",
 "financial_records":[ ... ]}
→ 200 {accepted, memory_changes}
→ 422 if a record_id already exists or a
      member_id is unknown
Option 3 · MCP

You expose an MCP server

We connect as an MCP client and call your tool for each family. Return a full Contract A payload, as structured output or JSON text. list_families is optional.

tool get_family_financial_data(family_id: str)
  → Contract A payload
tool list_families()            (optional)
  → [{"family_id": "F001", ...}]

transport: streamable HTTP  (http://host:port/mcp)
       or: stdio            (a command we can run)

Other tool or argument names are fine; tell us what they are. If your output isn't in Contract A shape, we map it on our side.

Member fields

FieldReq.Meaning
member_id✓Stable ID. Never reuse or renumber. M001
name✓Display name.
relationship✓Role in the family: father · mother · son · daughter · spouse · self · grandfather · grandmother. The context engine derives spouse_of and parent_of links from these values.
date_of_birth–ISO date. Used for life-stage reasoning, such as retirement horizon.
spouse_id–The member_id of their spouse.
parent_ids–The member_ids of their parents. Use these whenever a role word like daughter_in_law isn't enough to place someone. We derive siblings and grandparents ourselves.
other_relations–Any other link: [{"type": "grandparent_of", "member_id": "M304"}]

Record fields

FieldReq.Meaning
record_id✓Unique and stable. Records are immutable. To correct or update a value, send a new record with a new ID.
member_id✓Primary owner. Must appear in members.
co_owner_ids–Other owners of joint assets, loans or shared expenses.
type✓One of the ten types in section 04.
category✓snake_case subtype. salary · professional_fees · savings_account · mutual_funds · equity_demat · home_loan · term_life · household
description–Human-readable label shown as evidence in answers.
amount✓Decimal string, such as "250000", never a JSON number. Use null when the value could not be extracted.
currency✓ISO-4217 code. INR
frequency–monthly · quarterly · annual · one_time. Use null for balances and valuations.
entity–The account or counterparty: {entity_id?, entity_type, name, institution?}. Types: employer · bank_account · loan_account · investment_portfolio · property · insurance_policy. Send a stable entity_id where you can, such as a masked account number. Without one, we match on name.
attributes–String-to-string map for type-specific details. See section 04.
source✓{document_id, filename, document_type?, page?}. Shown to users as proof, so every record needs it.
valid_from✓ISO date from which the fact is true, such as the salary effective date or the statement date.
valid_until–ISO date, or null if open-ended.
as_of–Snapshot date for balances, valuations and outstanding loan amounts.
confidence✓Your extraction confidence, from 0 to 1. Records below 0.9 are flagged in answers.
supersedes–Optional hint naming the record_id this record replaces. We also infer this ourselves.

05Rules the context engine enforces

Payloads that break R1 to R5 are rejected with a validation error. R6 to R9 are not checked automatically but affect answer quality.

  1. Amounts are decimal strings. "250000" · "8.4" are accepted; 250000.5 · "2.5L" · "₹2,50,000" are rejected.
  2. Missing means null, never zero. If you could not read a value, send "amount": null. We exclude it and tell the user it is missing. A zero is treated as a real zero.
  3. Every owner exists. member_id and every co_owner_ids entry must appear in members.
  4. record_id is unique and immutable. Pushing an existing ID returns 422. Send a new record instead of editing an old one.
  5. Provenance on every record. source.document_id and source.filename are required.
  6. Dates are ISO YYYY-MM-DD and describe when the fact was true, not when you processed the document.
  7. Keep history. Send the April payslip and the October payslip as two records. Don't overwrite the first one. We work out which is current.
  8. Stable entity IDs. The same bank account across twelve statements should carry the same entity_id. Name variants like "HDFC Bank" and "HDFC BANK LTD" are handled, but IDs are safer.
  9. Keep the original currency. Send CAD or USD amounts with their real currency. We report them separately and never mix them into INR totals.
  10. Normalise to the owner. A salary credit in the father's account belongs to the father. Joint loans and property carry both owners.

06What we do with your records

This explains why the rules above matter.

RecordWhat happens when a newer one arrives
incomeOne current value per person and category. A salary from a new employer replaces the old salary. The old one stays in history as superseded.
balances, investments, loans, assets, insurance, expensesOne current value per person, category and entity. A newer statement for the same account replaces the older one.
transactionAlways added. It never replaces anything.
any record with a past valid_untilMarked ended. It stays in history and is left out of current totals.

Ordering uses as_of if present, otherwise valid_from. Consent and privacy are handled on our side, so send everything you extract.

07 · Decisions to agree before we start

  1. Gross or net income. Our affordability maths treats income amount as cash available each month. Please send take-home (net) amounts, or add attributes.gross_or_net with the value "gross" or "net".
  2. Category vocabulary. Use the categories shown in this document where they fit. If you need a new one, tell us so it is counted correctly. For example, a new kind of loan should still have type: "loan".
  3. Delivery mode. Choose pull or push from section 02, and share your host and port, or ask for ours.
  4. Family and member IDs. For the demo, keep F001 and M001 to M003 exactly as in the sample below.

09Done checklist

Check any payload without storing it: POST http://<context-engine-host>:8000/api/contract/validate. Send a full snapshot or a record batch. The response lists every error with its JSON path, plus warnings such as a loan without an EMI. If your pull endpoint is down or sends invalid data, the context engine falls back to the sample data on its own, so the demo keeps running.

  • /api/contract/validate returns "valid": true with no warnings for your output.
  • Your output validates against financial-data-v1.schema.json, using any JSON Schema validator.
  • No amounts are floats or contain currency symbols, and unreadable values are null.
  • Every record has source.document_id and source.filename.
  • Loans include attributes.emi.
  • Repeated statements for one account share an entity_id.
  • Older payslips and statements are sent as their own records, not overwritten.
  • A test call to the endpoint you chose (pull or push) returns 200 against the running context engine.
